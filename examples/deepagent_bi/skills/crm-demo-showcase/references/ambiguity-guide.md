# 歧义处理指南

## 核心原则

1. **能确定的不问**：信息明确时直接执行，不要为了演示而故意制造歧义
2. **不确定的要问**：字段可能有多种理解时，先列出可能性
3. **上下文继承**：利用对话历史，不重复询问
4. **组合查询分步**：复杂查询拆解步骤，展示推理过程

## 歧义类型与处理策略

### 类型1：字段歧义

**场景**：用户提到的字段名与系统标准字段不完全一致。

**示例**："查询商机贡献率"
- 可能理解：
  a) 商机签约金额占总额的百分比
  b) 签约金额 / 预测金额
  c) 其他自定义指标
- 处理：列出可能的理解，让用户选择

### 类型2：上下文依赖

**场景**：查询依赖于前序结果。

**示例**："这3个客户有什么关联的商机吗？"
- 处理：从上一步结果中提取客户名称，直接查询关联商机
- 不需要追问，因为"这3个客户"明确指代前序结果

### 类型3：公式计算

**场景**：查询包含计算公式。

**示例**："商机浮动准确率=预测金额-签约金额<200000"
- 处理：将公式转化为查询条件
- 展示计算逻辑：筛选预测金额与签约金额差值绝对值小于200000的商机

### 类型4：模糊表述

**场景**：用户表述不完整或有歧义。

**示例**："请查询商机名称、签约金额、商机贡献率，仅查询2条数据"
- 处理：
  - "商机贡献率"可能不是标准字段，需确认

### 类型5：复杂组合

**场景**：查询需要多步计算和关联。

**示例**："查询项目数排名在后30%的客户，展示客户信息，查询这些最近关联的商机任务"
- 处理：
  - 步骤1：查询所有客户的项目数分布
  - 步骤2：计算后30%分界值，筛选目标客户
  - 步骤3：查询这些客户最近关联的商机任务
  - 每步展示中间结果

## 歧义追问话术模板

```
我理解您想查询的是 [理解A]，但 [字段/条件] 可能有以下几种含义：
1. [理解1]
2. [理解2]

请问您指的是哪一种？
```

## 无歧义直接执行

当信息明确时，直接展示推理过程并执行：

```
好的，我来查询一下。

【查询】查询客户名称为"韦小二"关联的商机，展示商机名称、签约金额
【执行中...】
【结果】...
```
