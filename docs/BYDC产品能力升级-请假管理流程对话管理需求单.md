## 需求背景

### 业务背景

企业请假流程通常依赖 OA、HRM 或低代码表单系统完成。传统系统在表单创建、流程配置、字段维护和统计查询方面存在明显门槛：

1. **填写链路长**：员工需要进入固定入口，逐项填写请假类型、开始时间、结束时间、请假天数、请假原因、附件等字段。
2. **流程理解成本高**：员工并不关心底层表单、审批节点、状态流转，只希望通过自然语言表达“我要请假”。
3. **复杂表单容易中断**：用户可能先说请假事由，稍后才补充时间、附件或交接人，传统一次性提交模式不适合多轮补充。
4. **审批处理分散**：主管需要在多个页面查看申请、审批记录、历史请假天数和待处理列表。
5. **统计分析依赖配置**：HR 想查询某员工本月请假天数、某部门待审批数量或病假趋势，通常需要报表或 SQL 支持。

ByDC 已具备结构化本体管理、自然语言数据操作、对象挂载、视图查询等能力。通过把“请假管理流程”封装为可对话、可拆分、可追踪的业务操作，可以验证 ByDC 从“建模工具”升级为“业务流程对话管理平台”的产品价值。

### 能力升级背景

本次需求不是单纯增加一个请假表单，而是通过一个高频、清晰、可验证的企业流程，沉淀 ByDC 的对话式业务操作能力：

- **自然语言建模**：通过对话创建“请假申请”“审批记录”等结构化对象。
- **渐进式业务操作**：把复杂申请拆成“保存基础信息”“补充时间”“上传附件”“提交审批”等对象动作。
- **多轮会话状态管理**：允许用户分多轮补充信息，不丢失前文已收集字段。
- **对象视图联动查询**：通过“请假审批视图”关联申请与审批记录，一句话查看完整审批上下文。
- **语义化审批动作**：用户直接说“同意张三这次请假”，系统自动识别对象、记录、状态变更和审计日志。

## 需求目标

### 核心目标

让企业员工和审批人通过自然语言对话完成请假申请、补充、提交、审批、查询和统计，将原本依赖固定表单和多页面操作的请假流程，升级为可对话、可追踪、可审计的 ByDC 业务流程能力。

### 具体目标

1. **降低操作门槛**：员工无需理解对象、视图、动作等技术概念，直接表达“我要请假”即可启动流程。
2. **支持渐进式收集**：用户可以先说部分信息，再分轮补充时间、事由、附件、交接人等内容。
3. **提升审批效率**：审批人可通过一句话查看待审批申请、审批详情，并完成通过或驳回。
4. **强化业务可观测性**：HR 可用自然语言查询请假记录、审批状态、部门统计、人员维度汇总。
5. **沉淀标准样板**：将请假流程作为 ByDC 对话式业务管理的样板场景，后续复用于出差、报销、采购、入职等流程。

## 需求范围

### 功能范围

本次需求覆盖“请假管理流程”的端到端对话化管理，包含以下能力：

#### 1. 自然语言创建请假管理本体对象

用户可以通过对话创建并确认以下对象：

- **请假申请**：承载员工请假申请的核心信息。
- **审批记录**：承载审批人、审批结果、审批意见和审批时间。
- **请假审批视图**：关联申请与审批记录，支持跨对象查询。

对象创建后支持挂载到当前助理，供后续自然语言新增、修改、查询和审批。

#### 2. 对话式请假申请提交

系统支持用户通过自然语言发起请假：

```text
用户：我下周一到周三想请事假，家里有事。

Agent：收到，我先为您整理请假申请草稿：
- 申请人：当前用户
- 请假类型：事假
- 开始时间：2026-07-27
- 结束时间：2026-07-29
- 请假天数：3 天
- 申请理由：家里有事
- 申请状态：草稿

还缺少交接说明，是否需要补充？也可以直接提交审批。
```

系统需要支持从上下文推断申请人、时间范围、请假天数和状态，并在提交前进行二次确认。

#### 3. 渐进式业务操作收集

请假申请不要求用户一次性说完所有字段。系统将复杂业务操作拆成多个职责单一的对象动作：

| 动作名称 | 触发语义 | 处理字段 | 说明 |
|----------|----------|----------|------|
| 请假申请-草稿保存 | “我要请假”“帮我记一条请假” | 申请人、请假类型、申请理由、申请状态 | 创建草稿，允许缺少时间等必填字段 |
| 请假申请-时间补充 | “时间是下周一到周三” | 开始时间、结束时间、请假天数 | 补齐时间并重新计算天数 |
| 请假申请-信息补充 | “原因补充为家里有事” | 申请理由、交接说明、附件说明 | 补充非核心字段 |
| 请假申请-提交审批 | “确认提交”“发给主管审批” | 申请状态、提交时间、审批人 | 校验必填项后进入待审批 |
| 审批记录-保存 | “同意”“驳回”“需要补充材料” | 审批人、审批时间、审批结果、审批意见 | 写入审批记录 |
| 请假申请-状态更新 | 审批通过 / 驳回 / 撤回 | 申请状态、更新时间 | 同步主申请状态 |

该拆分使 Agent 每轮只处理少量语义明确的字段，避免在长对话中维护整张复杂表单造成遗漏或覆盖。

#### 4. 对话式审批处理

审批人可通过自然语言查看待审批事项并完成审批：

```text
用户：查看我待审批的请假申请。

Agent：当前共有 2 条待审批请假申请：

| 申请编号 | 申请人 | 请假类型 | 时间 | 天数 | 理由 |
|----------|--------|----------|------|------|------|
| LA20260723001 | 张三 | 事假 | 2026-07-27 至 2026-07-29 | 3 | 家里有事 |
| LA20260723002 | 李四 | 年假 | 2026-08-03 至 2026-08-04 | 2 | 休假 |

您可以说“同意张三的请假”或“驳回李四的请假并说明原因”。
```

审批时系统应自动创建审批记录，并同步更新请假申请状态。

#### 5. 自然语言查询与统计

系统支持如下查询：

- 查询某员工请假记录：`查询张三 7 月份的请假记录`
- 查询待审批申请：`查一下所有待我审批的请假`
- 查询状态：`张三这次请假审批到哪一步了`
- 统计请假天数：`统计研发部本月每个人的请假天数`
- 查询审批结果：`查询上周被驳回的请假申请`
- 查询视图数据：`显示所有请假申请及其审批信息`

查询结果优先使用结构化表格返回，统计类结果应说明统计口径。

### 非本次范围

以下内容暂不纳入本次 MVP：

1. 与真实 OA / HRM 系统进行双向数据同步。
2. 复杂多级审批流编排器。
3. 请假额度自动扣减与薪资联动计算。
4. 附件 OCR 自动识别病假单、证明文件。
5. 移动端原生通知和企业微信 / 钉钉消息推送。

## 用户场景

### 场景 1：员工分多轮提交请假申请

**角色**：员工张三

**场景描述**：
张三临时需要请事假，但一开始只确定了大概日期和原因，稍后才补充交接说明。系统需要支持分轮收集，不要求一次性完整提交。

**使用流程**：

1. 张三说：“我下周一到周三请事假，家里有事。”
2. Agent 创建请假申请草稿，自动识别请假类型、时间、天数和原因。
3. Agent 提示缺少交接说明，但不阻断草稿保存。
4. 张三补充：“手上的客户跟进交给李四。”
5. Agent 更新草稿中的交接说明。
6. 张三说：“确认提交审批。”
7. Agent 校验必填项，生成申请编号，状态变更为待审批。

**价值体现**：

- 用户按自然表达节奏补充信息。
- 系统结构化保存每轮信息，不依赖模型长期记忆。
- 提交前二次确认，降低误提交风险。

### 场景 2：主管一句话完成审批

**角色**：主管李四

**场景描述**：
李四每天需要处理多条请假申请。传统方式需要打开审批列表、进入详情页、查看字段、填写意见并提交。

**使用流程**：

1. 李四说：“查看我今天待审批的请假。”
2. Agent 返回待审批列表。
3. 李四说：“同意张三 7 月 27 到 29 号的请假，意见写同意。”
4. Agent 定位申请编号并展示将要执行的审批动作。
5. 李四确认。
6. 系统新增审批记录，并将请假申请状态更新为已通过。

**价值体现**：

- 审批动作从多页面点击缩短为一句话。
- 审批记录与申请状态自动联动。
- 所有写操作保留确认和审计日志。

### 场景 3：HR 自然语言统计请假情况

**角色**：HR 王敏

**场景描述**：
王敏需要统计研发部 7 月份各员工请假天数，并查看是否存在长时间请假或审批积压。

**使用流程**：

1. 王敏说：“统计研发部 7 月份每个人的请假天数。”
2. Agent 基于请假申请对象进行聚合查询，返回员工维度汇总。
3. 王敏继续说：“只看超过 3 天的人。”
4. Agent 基于上轮查询条件继续过滤。
5. 王敏说：“再查一下研发部还有哪些请假待审批。”
6. Agent 查询待审批状态记录并返回列表。

**价值体现**：

- HR 无需配置报表即可获得统计结果。
- 支持连续追问，保留部门、月份等上下文条件。
- 查询和统计都基于结构化对象，结果可追溯。

## 对话交互样例

### 样例 1：创建请假管理对象

```text
用户：帮我创建一套请假管理流程，包含请假申请、审批记录，还要能看到申请和审批结果。

Agent：收到，我建议创建以下结构：
1. 请假申请对象：记录申请人、请假类型、开始时间、结束时间、请假天数、申请理由、申请状态等信息。
2. 审批记录对象：记录审批人、审批时间、审批结果、审批意见、关联的请假申请编号。
3. 请假审批视图：关联请假申请和审批记录，用于查看完整审批信息。

是否按这个结构创建？

用户：确认创建。

Agent：请假申请对象、审批记录对象和请假审批视图已创建完成，并已挂载到当前助理。现在可以通过对话提交请假、审批请假或查询请假信息。
```

### 样例 2：渐进式提交申请

```text
用户：我想请假。

Agent：可以，请告诉我请假类型、开始时间、结束时间和请假理由。您也可以先说已经确定的信息，我会先保存草稿。

用户：病假，明天上午开始，可能请两天。

Agent：已为您保存请假草稿：
- 申请人：当前用户
- 请假类型：病假
- 开始时间：2026-07-24 上午
- 结束时间：待补充
- 请假天数：预计 2 天
- 申请状态：草稿

还需要补充准确结束时间和请假理由。

用户：到 7 月 25 日下午结束，原因是身体不舒服。

Agent：已补充请假信息：
- 结束时间：2026-07-25 下午
- 请假理由：身体不舒服
- 请假天数：2 天

确认提交审批吗？

用户：提交。

Agent：请假申请已提交，申请编号为 LA20260724001，当前状态为待审批。
```

### 样例 3：审批处理

```text
用户：同意张三的病假。

Agent：我找到 1 条匹配的待审批申请：
- 申请编号：LA20260724001

- 时间：2026-07-24 上午 至 2026-07-25 下午

1. 新增审批记录：审批结果为通过，审批人为当前用户。

确认执行吗？

用户：确认。

Agent：审批已完成。张三的请假申请已通过，审批记录已保存。
```

## 关键产品能力

### 1. 意图识别

系统需要识别以下核心意图：

| 意图 | 示例表达 | 期望动作 |
|------|----------|----------|
| 创建流程 | “帮我创建请假管理流程” | 创建对象、视图、动作 |
| 发起申请 | “我要请假”“帮我申请年假” | 创建或更新请假申请 |
| 补充申请 | “时间改成下周一到周二” | 更新草稿字段 |
| 提交审批 | “确认提交”“发给主管审批” | 校验并变更状态 |
| 审批处理 | “同意张三的请假”“驳回这条申请” | 新增审批记录并更新状态 |
| 查询记录 | “查询张三请假记录” | 查询请假申请或视图 |
| 统计分析 | “统计部门请假天数” | 聚合查询 |

### 2. 实体抽取

系统需要从自然语言中抽取以下实体：

- 人员：申请人、审批人、交接人。
- 时间：开始时间、结束时间、审批时间、统计周期。
- 类型：年假、事假、病假、调休等。
- 状态：草稿、待审批、已通过、已驳回等。
- 理由：请假原因、审批意见、交接说明。
- 范围：部门、月份、待审批人、申请编号。

### 3. 状态流转

请假申请推荐状态机：

```text
草稿 -> 待审批 -> 已通过
草稿 -> 待审批 -> 已驳回
草稿 -> 已撤回
待审批 -> 已撤回
已驳回 -> 草稿
```

状态流转规则：

1. 草稿状态允许补充、修改和删除。
2. 待审批状态允许审批人通过、驳回或退回补充。
3. 已通过状态默认不允许员工直接修改。
4. 已驳回状态允许员工基于原申请复制并重新提交。
5. 撤回操作需记录撤回时间和撤回人。

### 4. 安全确认

所有写操作必须二次确认：

- 创建对象 / 视图 / 动作前，展示结构摘要。
- 新增请假申请前，展示字段摘要。
- 修改请假时间、天数、状态前，展示变更前后。
- 审批通过或驳回前，展示申请编号和审批结果。
- 删除或撤回前，展示影响范围和不可逆提示。

### 5. 权限控制

| 角色 | 权限 |
|------|------|
| 员工 | 创建本人请假申请、查询本人记录、撤回本人待审批申请 |
| 直属主管 | 查询待本人审批申请、审批下属申请、查询审批历史 |
| HR | 查询全员请假记录、统计部门请假数据、导出报表 |
| 业务管理员 | 创建对象、配置视图、维护请假类型和规则 |

## 技术方案概要

### 技术架构

```text
用户自然语言输入
    ↓
意图识别与实体抽取
    ↓
会话状态管理
    ↓
对象动作编排
    ↓
结构化本体对象 / 视图 / 动作调用
    ↓
权限校验与业务规则校验
    ↓
数据写入 / 查询 / 聚合统计
    ↓
操作确认、结果返回与审计记录
```

### 核心模块

#### 1. 对话理解模块

- 识别用户当前意图。
- 抽取人员、时间、类型、理由、状态等实体。
- 将相对时间转换为明确日期。
- 对歧义表达进行追问，例如“下周”跨周边界、“请两天”未说明开始时间等。

#### 2. 会话状态模块

- 保存请假申请草稿的中间状态。
- 支持用户分轮补充、修改或取消。
- 记录本轮动作与历史字段来源。
- 在提交前合并为完整结构化对象。

#### 3. 对象动作编排模块

- 将自然语言意图映射到对象动作。
- 支持“草稿保存 -> 信息补充 -> 提交审批 -> 审批记录保存 -> 状态更新”的组合编排。
- 对每个动作执行前进行权限校验和字段校验。
- 高风险动作必须进入确认流程。

#### 4. 本体管理模块

- 创建并维护请假申请对象、审批记录对象、请假审批视图。
- 自动生成对象编码、字段编码和视图关联条件。
- 支持对象挂载到当前助理。
- 支持后续自然语言查询与操作。

#### 5. 审计与追踪模块

- 记录自然语言输入、识别意图、执行动作和结构化结果。
- 记录审批动作的操作人、时间、来源、结果。
- 支持按申请编号追溯完整流程。

## 可抽取到操作说明的素材

### 素材 1：产品能力说明

ByDC 可以把“请假管理流程”从固定表单升级为对话式业务管理流程。用户不需要理解对象、视图、动作等底层概念，只要通过自然语言表达“我要请假”“同意张三的请假”“统计本月请假天数”，Agent 就能完成信息收集、结构化写入、审批记录保存、状态更新和跨对象查询。

### 素材 2：渐进式操作说明

请假申请不要求用户一次性填完所有字段。Agent 会先把已识别的信息保存为草稿，再根据缺失字段逐步追问。用户后续补充的时间、理由、交接说明会写入同一条草稿记录，不会覆盖前文已确认的信息。提交审批前，Agent 会展示完整申请摘要，由用户确认后再执行写入或状态变更。

### 素材 3：审批动作说明

审批人可以直接通过自然语言完成审批。系统会先定位待审批申请，如果存在多条候选记录，会展示候选列表让审批人选择。确认后，系统会新增审批记录，并同步更新请假申请状态。审批记录包含审批人、审批时间、审批结果、审批意见和关联申请编号，便于后续审计和追溯。

### 素材 4：查询统计说明

请假申请和审批记录通过“请假审批视图”关联后，用户可以一句话查看完整审批信息。例如“查询张三 7 月份请假记录”“显示所有待审批请假”“统计研发部本月每个人请假天数”。统计结果会说明时间范围、状态口径和聚合维度，避免用户误解。
