## 需求背景

### 业务背景

当前 ByDC 产品在本体建模和数据对象管理方面，已经具备了完善的技术能力。但在用户使用过程中，我们发现以下痛点：

1. **技术门槛高**：用户需要理解本体、对象、视图、动作等技术概念，学习成本较高
2. **操作流程复杂**：创建一个完整的业务对象需要经过多个页面、多个步骤的配置
3. **开发依赖重**：业务人员有新的数据需求时，仍需依赖技术人员开发和配置
4. **迭代效率低**：从需求提出到功能上线，周期长，响应慢

### 市场趋势

- **AI 原生应用兴起**：越来越多的企业级产品开始引入自然语言交互能力
- **低代码/零代码趋势**：业务人员希望自主完成数据建模，减少对技术团队的依赖
- **竞品压力**：Palantir Foundry、Snowflake 等竞品已推出类似的自然语言建模能力

### 用户反馈

从最近 3 个月的客户访谈和工单统计来看：

- **某金融客户**反馈：销售部门想快速搭建客户跟进表，但需要等技术团队排期 2 周才能完成
- **某制造企业**反馈：业务人员不理解"视图"和"对象"的区别，导致建模经常出错
- **某零售企业**反馈：每次新建数据表都要填写大量配置项，操作繁琐

## 需求目标

### 核心目标

**让业务人员通过自然语言对话，零代码完成本体建模和数据对象创建，将建模时间从"小时"级缩短到"分钟"级。**

### 具体目标

1. **降低使用门槛**：业务人员无需学习技术概念，用说的方式就能完成建模
2. **提升操作效率**：从 20 分钟的表单填写缩短到 3 分钟的对话交互
3. **减少开发依赖**：业务需求不再依赖技术团队排期，自主完成 80% 的建模工作
4. **提升产品竞争力**：打造差异化能力，树立 AI 原生数据平台的品牌形象

## 需求范围

### 功能范围

本次需求涵盖以下功能模块：

#### 1. 自然语言创建本体对象

**场景**：用户希望创建一个新的业务对象（如"客户信息"、"订单记录"）

**交互示例**：

```
用户："帮我创建一个客户管理对象，包含客户名称、联系电话、所属行业、客户等级这些字段"

Agent："收到，我为您设计的对象结构如下：
- 对象名称：客户管理
- 对象编码：customer_management
- 字段清单：
  - 客户名称（文本）
  - 联系电话（文本）
  - 所属行业（文本）
  - 客户等级（文本）
  
这样可以吗？或者需要调整？"

用户："再加一个'年签约金额'字段，数字类型"

Agent："好的，已添加'年签约金额（数字）'字段。确认创建吗？"

用户："确认"

Agent："客户管理对象创建成功！已自动挂载到您的助理，现在可以开始录入数据了。"
```

**功能要点**：
- 支持字段类型自动识别（文本、数字、日期、枚举等）
- 支持多轮对话补充和修改字段
- 自动生成对象编码和数据表结构
- 创建成功后自动挂载到当前用户的数字助理

#### 2. 自然语言创建视图

**场景**：用户希望关联多个对象，实现跨表查询

**交互示例**：

```
用户："创建一个客户订单视图，关联客户和订单两个对象"

Agent："收到，我为您设计的视图结构如下：
- 视图名称：客户订单视图
- 关联对象：客户管理、订单记录
- 关联条件：通过'客户编号'字段关联
- 视图字段：
  - 客户名称
  - 客户等级
  - 订单金额
  - 订单状态
  
这样可以查到每个客户的所有订单信息。确认创建吗？"

用户："确认"

Agent："客户订单视图创建成功！现在可以通过自然语言查询了，比如'查询VIP客户的订单总金额'。"
```

**功能要点**：
- 自动识别对象间的关联关系
- 智能推荐视图应包含的字段
- 支持一对多、多对多关联关系
- 自动生成视图查询逻辑

#### 3. 自然语言创建动作

**场景**：用户希望定义业务操作逻辑（如审批、流转、计算）

**交互示例**：

```
用户："给订单对象添加一个'审批通过'动作，触发后自动把订单状态改为'已审批'，并记录审批时间"

Agent："收到，我为您设计的动作如下：
- 动作名称：审批通过
- 触发条件：手动触发
- 执行逻辑：
  1. 更新订单状态 → '已审批'
  2. 记录审批时间 → 当前时间
  3. 记录审批人 → 当前用户
  
确认创建吗？"

用户："确认"

Agent："审批通过动作创建成功！现在查询订单时可以直接说'把这个订单审批通过'。"
```

**功能要点**：
- 支持字段更新、数据计算、状态流转等常见业务逻辑
- 支持条件判断和分支逻辑
- 自动记录操作日志
- 可配置触发条件（手动触发、自动触发）

#### 4. 自然语言创建本体库

**场景**：用户希望创建一个完整的本体库，包含多个对象和视图

**交互示例**：

```
用户："帮我创建一个CRM本体库，包括客户、商机、跟进记录这几个对象"

Agent："收到，我为您设计的CRM本体库结构如下：

本体库名称：CRM业务管理
包含对象：
1. 客户管理（客户名称、联系方式、所属行业...）
2. 商机管理（商机名称、预计金额、商机阶段...）
3. 跟进记录（跟进时间、跟进方式、跟进内容...）

建议的视图：
1. 客户商机视图（关联客户和商机）
2. 商机跟进视图（关联商机和跟进记录）

这样可以支持完整的客户跟进流程。需要我继续细化字段定义吗？"

用户："可以，继续"

Agent："好的，我来逐个确认对象字段..."
```

**功能要点**：
- 支持批量创建多个关联对象
- 智能推荐对象间的关系
- 自动生成业务视图
- 支持从模板快速创建（如 CRM、ERP、项目管理等）

## 技术方案概要

### 技术架构

```
用户自然语言输入
    ↓
意图识别与实体抽取
    ↓
知识图谱推理（字段推荐、关系识别）
    ↓
本体定义生成（Schema）
    ↓
数据表创建（DDL执行）
    ↓
对象/视图注册
    ↓
挂载到用户助理
```

### 核心技术能力

#### 1. 自然语言理解（NLU）

- **意图识别**：识别用户是要创建对象、视图还是动作
- **实体抽取**：提取对象名称、字段名称、字段类型、关联关系
- **语义归一化**：处理不同表达方式（如"联系方式"="电话"="手机号"）

#### 2. 知识图谱推理

- **字段推荐**：基于领域知识图谱，推荐常见字段
  - 例如创建"客户对象"时，自动推荐"客户名称、联系方式、所属行业"
- **关系识别**：自动发现对象间的关联关系
  - 例如"订单"和"客户"通过"客户编号"关联
- **类型推断**：根据字段名称和语义，推断字段类型
  - 例如"金额"推断为数字类型，"创建时间"推断为日期类型

#### 3. 本体建模引擎

- **Schema 生成**：将用户意图转换为本体定义（OWL/RDF）
- **DDL 生成**：根据本体定义生成数据表 DDL
- **关系映射**：建立对象间的关系映射（外键、关联表）
- **校验机制**：检查对象/字段命名冲突、循环依赖等问题

#### 4. 多轮对话管理

- **状态管理**：记录对话上下文，支持多轮确认和修改
- **缺失信息追问**：自动识别缺失的必填字段，主动追问
- **二次确认**：所有创建操作前进行二次确认，防止误操作

### 技术挑战与方案

| 挑战 | 解决方案 |
|------|----------|
| 字段类型识别不准确 | 引入领域知识库 + 用户反馈学习机制 |
| 关联关系推断错误 | 采用置信度评分 + 人工确认机制 |
| 命名冲突处理 | 自动生成唯一编码 + 提示用户重命名 |
| 复杂业务逻辑表达 | 采用 DSL（领域特定语言）+ 模板库 |
| 性能瓶颈 | 异步创建 + 进度反馈 + 缓存优化 |
